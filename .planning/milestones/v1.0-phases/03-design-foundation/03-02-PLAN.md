<task type="auto">
  <name>Task 1: Create WCAG contrast verification script and verify all token combinations pass</name>
  <files>scripts/verify-contrast.mjs, package.json</files>
  <action>
1. Install the `wcag-contrast` package as a dev dependency:
   ```bash
   npm install --save-dev wcag-contrast
   ```

2. Create `scripts/verify-contrast.mjs` that programmatically verifies all custom text-on-background combinations against WCAG AA thresholds.

   **Step 1 in the script:** Convert the OKLCH token values from `globals.css` to their sRGB hex equivalents. Use a browser or oklch.net to get the actual hex values for each OKLCH token. The script stores these as hex constants.

   **Step 2:** Define ALL combinations to verify. Cover:

   **Body text (4.5:1 minimum):**
   - snow-100 on alpine-950 (body text on deepest bg)
   - snow-100 on alpine-900 (body text on page bg)
   - snow-100 on alpine-800 (body text on card/surface)
   - snow-100 on alpine-700 (body text on elevated surface)
   - snow-200 on alpine-900 (secondary text on page bg)
   - snow-200 on alpine-800 (secondary text on card)

   **Large text / headings (3:1 minimum):**
   - snow-50 on alpine-950 (h1 on deepest bg)
   - snow-50 on alpine-900 (h1 on page bg)
   - snow-50 on alpine-800 (h1 on card)

   **Accent text — large text threshold (3:1 minimum):**
   - frost-500 on alpine-900 (interactive text on page bg)
   - frost-500 on alpine-800 (interactive text on card)
   - frost-400 on alpine-900 (hover state text)
   - ember-500 on alpine-900 (highlight text on page bg)
   - ember-500 on alpine-800 (highlight text on card)
   - ember-400 on alpine-900 (hover highlight)

   **Semantic colors — large text threshold (3:1 minimum):**
   - pine-500 on alpine-900 (success on page bg)
   - pine-400 on alpine-800 (success on card)
   - rust-500 on alpine-900 (error on page bg)
   - rust-400 on alpine-800 (error on card)
   - amber-500 on alpine-900 (warning on page bg)
   - amber-400 on alpine-800 (warning on card)

   **Caption/muted text (4.5:1 minimum for body-sized caption):**
   - granite-400 on alpine-900 (caption on page bg)
   - granite-400 on alpine-800 (caption on card)
   - granite-300 on alpine-900 (slightly brighter caption)

   **Step 3:** For each combination, call `hex(fg, bg)` from wcag-contrast, compare against the minimum ratio, print PASS/FAIL with the actual ratio and label.

   **Step 4:** Exit with code 0 if all pass, code 1 if any fail.

   **Step 5:** Add a summary line at the end: `X/Y combinations passed`.

3. Add a script to `package.json`:
   ```json
   "verify-contrast": "node scripts/verify-contrast.mjs"
   ```

4. Run `npm run verify-contrast`. If any combinations FAIL:
   - Adjust the OKLCH lightness values in `globals.css` `@theme` to meet the threshold
   - Increase lightness for foreground colors that are too dark
   - Re-derive hex values for the adjusted tokens
   - Update the hex values in verify-contrast.mjs
   - Re-run until all pass

**IMPORTANT:** The hex values in the script MUST match the browser-resolved sRGB values of the OKLCH tokens in globals.css. Use oklch.net, the CSS Color Level 4 conversion, or browser DevTools computed styles to derive accurate hex equivalents. Do NOT guess or approximate.

**IMPORTANT:** Granite-400 used for captions may fail 4.5:1 against dark backgrounds. If so, increase its lightness in the OKLCH value (e.g., from 0.55 to 0.60+). Contrast on dark themes often requires lighter neutrals than expected.
  </action>

**CHECKPOINT: Human visual verification required.**

What was built:
- Complete Swiss Alps design token system (color palette + typography)
- Custom color palette: alpine dark backgrounds, granite neutrals, snow text, frost cyan accent, ember amber accent, pine/rust/amber semantics
- Typography system: JetBrains Mono for headings with cyan glow on h1, Inter for body text
- Base heading hierarchy: h1 bold + glow, h2 semi-bold, h3/h4 regular
- All combinations WCAG AA verified by automated script

Present the following verification steps to the user:

1. Start the dev server: `npm run dev`
2. Open http://localhost:3000 in your browser
3. Check these visual elements:

**Typography:**
- Headings should render in JetBrains Mono (monospace/technical feel)
- Body text should render in Inter (clean sans-serif)
- H1 page title should have a subtle cyan glow (text-shadow)
- Body text should be warm off-white (not pure white, slightly cream)

**Background:**
- Page background should be a very dark green-tinted shade (not pure black)
- If any cards or surfaces are visible, they should be slightly lighter than the background

**Overall feel:**
- Dark, professional, tech-meets-nature atmosphere
- The cyan glow should feel like a hologram terminal, not a neon sign
- Text should be comfortable to read (not straining)

4. Check the browser DevTools:
- Inspect an h1 — should show `font-family` including "JetBrains Mono"
- Inspect body text — should show `font-family` including "Inter"
- Inspect body — should show the alpine-900 background color

**Note:** Existing component colors (gray, cyan, etc.) should still work. The new tokens are additive — they exist alongside defaults. Components won't use the new tokens until Phase 4.

**Resume signal:** Type "approved" if the visual feel matches expectations, or describe what needs adjustment (e.g., "glow too bright", "background too green", "headings too thin"). If adjustments are needed, update token values in globals.css accordingly.
