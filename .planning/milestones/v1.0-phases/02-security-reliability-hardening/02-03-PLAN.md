  <files>public/service-worker.js, scripts/inject-build-hash.mjs</files>
  <action>
    **Step 1: Rewrite public/service-worker.js**
    Replace the entire service worker with a new implementation. The file serves as a template -- `__BUILD_HASH__` is replaced by the post-build script.

    Cache names:
    ```javascript
    const BUILD_HASH = '__BUILD_HASH__';
    const STATIC_CACHE = `static-${BUILD_HASH}`;
    const IMAGE_CACHE = `images-${BUILD_HASH}`;
    const DYNAMIC_CACHE = `dynamic-${BUILD_HASH}`;
    ```

    Install event:
    - Precache critical assets: `['/', '/offline']` into STATIC_CACHE
    - Call `self.skipWaiting()` for silent activation (per user decision: silent background refresh)

    Activate event:
    - Delete ALL caches whose name does NOT end with the current BUILD_HASH (simpler and more reliable than prefix-matching)
    - Call `self.clients.claim()` to take control immediately

    Fetch event -- strategy per asset type (per user decisions):
    1. Skip non-GET requests (return immediately)
    2. Skip chrome-extension: protocol
    3. **Network-only** for `/api/` routes: `return` without responding (let browser handle normally)
    4. **Cache-first** for fingerprinted static assets: paths matching `/_next/static/`, `/images/`, or font extensions (`.woff2`, `.woff`, `.ttf`, `.otf`). Use STATIC_CACHE. On cache miss, fetch from network, cache the response, return it. On network error, return undefined.
    5. **Stale-while-revalidate** for HTML pages: check `request.mode === 'navigate'` OR accept header includes `text/html`. Serve from DYNAMIC_CACHE if available, simultaneously fetch fresh copy and update cache. If no cached version exists, await the network fetch. On network error with no cache, fall back to cached `/offline` page.
    6. **Cache-first** for images: paths matching `/_next/image` or `request.destination === 'image'`. Use IMAGE_CACHE.
    7. **Network-first** for everything else: try network first, cache successful responses in DYNAMIC_CACHE, on network failure serve from cache.

    Implement these as separate async helper functions: `cacheFirst(request, cacheName)`, `staleWhileRevalidate(request, cacheName)`, `networkFirst(request, cacheName)`.

    Keep the message event listener for SKIP_WAITING.
    Remove all `console.log` statements from the service worker (they were for debugging; the service worker should be silent in production).

    **Step 2: Create scripts/inject-build-hash.mjs**
    This script runs as a postbuild step:
    1. Read `.next/BUILD_ID` from the project root (created by `next build`)
    2. Read `public/service-worker.js`
    3. Replace all occurrences of `__BUILD_HASH__` with the actual build ID
    4. Write the modified content back to `public/service-worker.js`
    5. Log: `Injected build hash ${buildId} into service worker`
    6. Use Node.js built-in `fs` and `path` modules (import from 'fs' and 'path')
    7. Use `process.cwd()` for the base directory
    8. Handle the case where `.next/BUILD_ID` doesn't exist (log error and exit gracefully -- this would only happen if the script runs before next build)

    IMPORTANT: The script modifies `public/service-worker.js` in place. This is intentional -- Vercel deploys the contents of `public/` as static assets, so the modified file with the real hash is what gets deployed. For local development, `git checkout public/service-worker.js` can restore the template, but since the dev server doesn't use the service worker (production-only registration), this is a non-issue.
  </action>

             if (newWorker.state === 'activated') {
               // New version active -- next navigation will use fresh assets
             }
           });
         }
       });
