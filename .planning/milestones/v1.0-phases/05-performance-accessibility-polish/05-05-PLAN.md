**Fix 1 -- Synchronous initialization in useReducedMotion (lib/useReducedMotion.ts):**

Replace the current `useState(false)` initialization with a lazy initializer that reads `matchMedia` synchronously on the client:

```typescript
'use client';

import { useEffect, useState } from 'react';

function getInitialValue(): boolean {
  if (typeof window === 'undefined') return false;
  return window.matchMedia('(prefers-reduced-motion: reduce)').matches;
}

export function useReducedMotion() {
  const [prefersReducedMotion, setPrefersReducedMotion] = useState(getInitialValue);

  useEffect(() => {
    const mediaQuery = window.matchMedia('(prefers-reduced-motion: reduce)');
    setPrefersReducedMotion(mediaQuery.matches);

    const listener = (event: MediaQueryListEvent) => {
      setPrefersReducedMotion(event.matches);
    };

    mediaQuery.addEventListener('change', listener);
    return () => mediaQuery.removeEventListener('change', listener);
  }, []);

  return prefersReducedMotion;
}
```

Key: `useState(getInitialValue)` calls `getInitialValue` as a lazy initializer. On the client, this reads `matchMedia` synchronously during the FIRST render, so `prefersReducedMotion` is immediately `true` when the OS setting is enabled. On the server (SSR), it returns `false`. Since this is a `'use client'` component, the initializer runs on the client during hydration, producing the correct value from the first render. No more hydration race -- components receive the correct value immediately and never render with `opacity:0` initial states.

The `useEffect` is kept for two reasons: (1) to sync if the preference changes at runtime (user toggles setting while page is open), and (2) as a safety net for edge cases where the lazy initializer might not have access to `window` during SSR.

**Fix 2 -- Replace universal CSS guard with targeted approach (app/globals.css):**

In the `@media (prefers-reduced-motion: reduce)` block at the bottom of globals.css, replace the universal `*` selector block (lines 369-376) with a targeted approach that only disables MOTION-related transitions (transform, translate, rotate, scale) while preserving visual transitions (color, opacity, background-color, border-color, box-shadow):

Replace this:
```css
/* Phase 5: Universal fallback -- catches all CSS transitions and animations */
*,
*::before,
*::after {
  transition-duration: 0.01ms !important;
  animation-duration: 0.01ms !important;
  animation-iteration-count: 1 !important;
}
```

With this:
```css
/* Phase 5: Universal fallback -- disable motion transitions but preserve visual state changes */
*,
*::before,
*::after {
  animation-duration: 0.01ms !important;
  animation-iteration-count: 1 !important;
  transition-property: color, background-color, border-color, outline-color,
    text-decoration-color, fill, stroke, opacity, box-shadow, filter,
    backdrop-filter !important;
}
```

This approach overrides `transition-property` to ONLY allow non-motion properties. Any element with `transition-all` or `transition-transform` will have its transition-property overridden to the safe list above. Transform, translate, rotate, and scale transitions are excluded, so motion is eliminated. But color changes, opacity fades, background shifts, box-shadow glows, and other visual state changes continue to work normally.

The `animation-duration: 0.01ms` and `animation-iteration-count: 1` lines are kept to kill CSS @keyframes animations (like `contour-drift`), which is correct behavior.

IMPORTANT: Keep all the other rules in the `@media (prefers-reduced-motion: reduce)` block intact -- the Phase 4 guards (.contour-animate, .ambient-glow, .glow-frost, .glow-ember) and Phase 5 Tailwind utility guards (.animate-pulse, .animate-spin, .animate-bounce) should remain unchanged.
