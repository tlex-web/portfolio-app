<task type="auto">
  <name>Task 1: Fix texture lifecycle in useProgressiveTextures</name>
  <files>lib/useProgressiveTextures.ts</files>
  <action>
Fix four critical texture leak bugs in lib/useProgressiveTextures.ts:

**Bug 1 -- Dispose intermediate textures after hot-swap (Phase 1, lines 66-79):**
After `existing.image = thumbTexture.image; existing.needsUpdate = true;`, add `thumbTexture.dispose();` to free the intermediate GPU texture handle. The .image data has been transferred to the persistent texture; the intermediate wrapper is no longer needed.

Apply the same fix in Phase 2 (lines 146-160): after `existing.image = fullTexture.image; existing.needsUpdate = true;`, add `fullTexture.dispose();`.

**Bug 2 -- Track in-flight textures for cleanup on effect teardown:**
Create a `Set<THREE.Texture>` ref (e.g., `inFlightRef`) at the hook level. In both Phase 1 and Phase 2 TextureLoader.load() success callbacks, add the received texture to the set BEFORE the cancelled check, and remove it after dispose. In the cleanup function of both effects, iterate the set and dispose + delete each texture. This ensures textures created during the cancelled window (between load start and cancelled=true) are still freed.

Phase 1 cleanup (line 110-112) should become:
```
return () => {
  cancelled = true;
  inFlightRef.current.forEach(t => { t.dispose(); });
  inFlightRef.current.clear();
};
```

Phase 2 cleanup (line 189-191) should follow the same pattern.

**Bug 3 -- Dispose old placeholders before re-allocation (Phase 1, lines 54-60):**
Before creating new placeholder textures (the `if (texturesRef.current.length !== images.length)` block), dispose existing textures in texturesRef.current first:
```
texturesRef.current.forEach(t => t.dispose());
```
This prevents orphaned GPU textures when the images array changes length.

**Bug 4 -- Limit Phase 2 concurrent loads to active + adjacent only (3 max):**
In the Phase 2 priority array (lines 123-133), change it to only include the 3 proximity-based indices (activeIndex, activeIndex+1, activeIndex-1). Remove the spread of remaining indices. This means only 3 full-res textures load per activeIndex change instead of all images. The remaining images keep their thumbnails until the user navigates near them. This dramatically reduces GPU pressure during navigation.

The priority array should become:
```
const priority = [
  activeIndex,
  (activeIndex + 1) % len,
  (activeIndex - 1 + len) % len,
];
```

IMPORTANT: Keep the existing unmount cleanup effect (lines 196-204) as-is -- it correctly disposes all persistent textures on component unmount. The in-flight tracking is ADDITIONAL cleanup for the per-effect teardown.
