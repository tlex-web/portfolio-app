  <files>lib/useProgressiveTextures.ts, components/PhotoCarousel3D.tsx</files>
  <action>
Create `lib/useProgressiveTextures.ts`:
- Export a `useProgressiveTextures(images: LandscapeImage[], activeIndex: number)` hook
- Mark file as `'use client'`
- Use `THREE.TextureLoader` directly (NOT drei's `useTexture` which blocks on Suspense)
- Phase 1 (on mount): Load ALL thumbnail textures from `image.thumbnailSrc` in parallel. These are 13-29KB and load in under 100ms. Store textures in a `useRef<THREE.Texture[]>` for stability across renders. Track load state per-image as `'loading' | 'thumb' | 'full'` in `useState`.
- Phase 2 (on activeIndex change): Load full-resolution textures from `image.src` sequentially by priority: active image first, then adjacent (activeIndex+1, activeIndex-1 wrapping), then remaining. For each loaded full-res texture, hot-swap by setting `existingTexture.image = fullTexture.image; existingTexture.needsUpdate = true;` -- this updates the GPU texture in-place without component remount.
- Set `texture.minFilter = THREE.LinearFilter`, `texture.generateMipmaps = false` on all textures for consistent rendering.
- Return `{ textures: THREE.Texture[], loadState: ('loading' | 'thumb' | 'full')[], allThumbsLoaded: boolean }`.
- Include cleanup: cancel in-flight loads on unmount, `texture.dispose()` on unmount.
- Phase 2 effect must cancel and re-prioritize when `activeIndex` changes (use a `cancelled` flag in the effect cleanup).

Refactor `components/PhotoCarousel3D.tsx` Carousel component:
- Remove `import { useTexture, Preload } from '@react-three/drei'` -- replace `useTexture` with `useProgressiveTextures`. Keep `Html` and `Environment` imports from drei.
- Remove the `useTexture(images.map(img => img.src))` call (line ~124) and the `textureArray` useMemo that normalizes it.
- Call `const { textures, loadState, allThumbsLoaded } = useProgressiveTextures(images, activeIndex);` instead.

- Pass `textures[i]` to each PhotoFrame (same as current pattern).
- Remove `<Preload all />` from the Suspense block (no longer needed since we manage loading manually).
- The Suspense boundary can remain but its fallback is less critical now since thumbnails load fast.
