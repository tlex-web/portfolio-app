**Weight decision: `regular`** (Default (researcher) — confirm at plan review). The research left `light` or `regular` open. `regular` wins for three reasons:
1. **Stroke weight.** Phosphor regular draws a 16/256 stroke, about 1.25 px at 20 px and 1.5 px at 24 px. That is the closest match to the 1 px contour linework at the sizes used here. `light` falls below 1 px at 20 px and renders faint on low-DPI Windows screens, which puts meaningful glyphs at risk of failing 3:1 non-text contrast ([UUPM] `icon-style-consistent`, Icon Contrast rule).
2. **No context needed.** `regular` is Phosphor's default weight. The `dist/ssr` build has no `IconContext`, so with `regular` no `weight` prop is needed anywhere and drift is impossible.
3. **One style.** Every icon is outline style. No `fill` or `duotone` at any hierarchy level ([UUPM] Filled vs Outline Discipline).

**Icon size tokens:** 16 px (inline with 14 px text), 20 px (default, inline with 16 px text), 24 px (standalone glyph inside an icon or menu button). No other sizes.

**Icon semantics** ([UUPM] `icon-context`):
- An icon beside visible text gets `aria-hidden="true"`.
- An icon-only control gets an accessible name on the control.
- Phase 7 has no standalone meaningful icons without text.

**Brand logos:** `GithubLogo` and `LinkedinLogo` are Phosphor's own marks. They render in `currentColor` and must not be recoloured to brand colours ([UUPM] Correct Brand Logos).

**Not icons:** the terminal prompt glyph `❯` in `HologramTerminalDemo` is a typographic character in monospaced data text, not an icon. It stays as text. Arrows inside prose copy ("Next →") count as text too, but Phase 7 shell copy uses none.

## Spacing Scale

Declared values (all multiples of 4; they map to Tailwind v4's 4 px spacing base):

| Token | Value | Tailwind | Usage |
|-------|-------|----------|-------|
| xs | 4px | `1` | Icon-to-label gap inside a link or button |
| sm | 8px | `2` | Gap between adjacent nav links (touch spacing), compact stacks |
| md | 16px | `4` | Default element spacing; mobile gutter; skip-link inset; button group gap |
| lg | 24px | `6` | Button horizontal padding; tablet gutter; footer bottom-row padding |
| xl | 32px | `8` | Desktop gutter; card padding; gap between footer columns |
| 2xl | 48px | `12` | Footer vertical padding; space between major blocks |
| 3xl | 64px | `16` | Nav height (`--nav-h`); edge-page top and bottom padding at every breakpoint |

**Exceptions:**
- **Touch targets:** every nav link, menu button, footer link and button is at least **44 px** tall (`min-h-11`), and mobile menu rows are **48 px** (`min-h-12`). 44 is a minimum hit size, not a spacing step (SHELL-02; [UUPM] `touch-target-size`; WCAG 2.2 `web-target-size` needs 24 px, and the project targets 44).
- **Focus geometry:** a 2 px outline width and a 2 px offset (a stroke, not spacing).
- **Banned in new Phase 7 code:** half steps (`0.5`, `1.5`, `2.5`, `3.5`) and arbitrary pixel spacing (`p-[13px]`).

### Layout widths, gutters, breakpoints, layers

| Property | Value |
|----------|-------|
| Container | `mx-auto w-full max-w-6xl` (1152 px) for shell, edge pages and Contact |
| Gutters | 16 px below 640 px (`px-4`), 24 px from 640 px (`sm:px-6`), 32 px from 1024 px (`lg:px-8`) |
| Prose measure | `max-w-prose` (65ch) for body copy on edge pages and Contact ([UUPM] `line-length-control`) |
| Breakpoints | 375 px (baseline), `md` 768 px (desktop nav appears), `lg` 1024 px, 1440 px (baseline). Visual baselines capture 375, 768 and 1440 (PITFALLS 2; [UUPM] `breakpoint-consistency`) |
| `--nav-h` | `64px` (`h-16`) at every breakpoint |
| Scroll offset | `html { scroll-padding-top: calc(var(--nav-h) + 16px); }`, so the sticky nav never hides focused or anchored content ([UUPM] `focus-not-obscured`, WCAG 2.2 AA, severity High) |
| z-index scale | `--z-nav: 40` (sticky SiteNav), `--z-menu: 50` (mobile menu panel), `--z-skip: 60` (focused skip link). 70 and above are reserved for the Phase 10 lightbox ([UUPM] `z-index-management`) |
| Radius | `rounded-sm` (4 px) for buttons, inputs, focus outline and skip link; `rounded-lg` (8 px) for panels and cards. No other radii in new code. Flat survey-map look: no pill shapes in the shell |
| Elevation | None in the shell. Flat surfaces separated by 1 px `line` borders. Legacy `stratum-*` shadows and `glow-*` utilities stay only where pages still use them, and new code must not use them ([UUPM] `elevation-consistent`) |

### Stock → v2 collapse map (build step 8, `dark:` removal)

The order follows PITFALLS 3:
1. **Neutralise** with zero markup change: `@custom-variant dark (&:where(.dark, .dark *));`, `:root { color-scheme: dark; }` and `<html class="dark">`. The light baselines now equal the dark baselines.

## Shell Contract (SHELL-01, SHELL-02, SHELL-03)

### Structure

```
app/layout.tsx (root; keeps await headers(); <html lang="en" class="dark …fonts">; body.font-body)
└─ app/(site)/layout.tsx → <SiteChrome>{children}</SiteChrome>
   SiteChrome (Server):  <SkipLink/>  <SiteNav/>  <main id="main-content" tabIndex={-1}>{children}</main>  <SiteFooter/>   (inside MotionProvider)
app/not-found.tsx       → <SiteChrome><NotFoundBody/></SiteChrome>            (root not-found renders the chrome itself)

app/global-error.tsx    → own <html lang="en" class="dark …fonts"><body> + <SiteChrome variant="static"><ErrorBody reset/></SiteChrome>
```

**Rules:**
- **Landmarks.** Each route renders exactly one `<header>` (banner) holding exactly one `<nav aria-label="Primary">`, exactly one `<main id="main-content">` and one `<footer>` (contentinfo). The footer contains **no** `<nav>`.
- **Per-page shells removed.** Delete the `Header` and `Footer` imports from all pages in the same commit as the `git mv` into `app/(site)/` (PITFALLS 7).
- **Home.** `app/page.tsx` renames its inner `id="main-content"` div to `id="home-content"`. The hero CTA `href="#main-content"` becomes `href="#home-content"`, otherwise the scroll-past-hero action would target the top of `main`. Strip `GlassmorphismNav` from `Hero3DMountain` (ARCHITECTURE §1).
- **`global-error` variant.** `variant="static"` renders the nav links as plain `<a>` elements with no `usePathname`, no current indicator and no mobile-menu state. The links are always visible in a wrapping row, so a broken shell hook cannot crash the fallback. This is the one documented exception to the current-page indicator.
