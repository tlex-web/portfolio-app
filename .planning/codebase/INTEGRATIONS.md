# External Integrations

**Analysis Date:** 2026-02-16

## APIs & External Services

**Email Service:**
- Resend - Transactional email for contact/feedback form
  - SDK/Client: `resend` (v6.9.2)
  - Auth: `RESEND_API_KEY` environment variable
  - Implementation: `lib/email.ts` with `sendFeedbackEmail()` function
  - Usage: Sends formatted HTML/text emails when users submit feedback via `/api/feedback`
  - Features: Branded email templates, reply-to support, lazy client initialization

**Analytics & Monitoring:**
- Vercel Analytics - Usage analytics and page view tracking
  - SDK/Client: `@vercel/analytics` (v1.6.1)
  - Auth: Automatic when deployed to Vercel (no API key needed)
  - Implementation: `app/layout.tsx` with `<Analytics />` component

- Vercel Speed Insights - Web vitals and performance monitoring
  - SDK/Client: `@vercel/speed-insights` (v1.3.1)
  - Auth: Automatic when deployed to Vercel
  - Implementation: `app/layout.tsx` with `<SpeedInsights />` component

**Content Delivery:**
- Google Fonts - Font serving for typography
  - Implementation: Preconnect hints in `app/layout.tsx`
  - Domains: `fonts.googleapis.com`, `fonts.gstatic.com`

**Three.js Assets:**
- External CDNs for 3D model loaders and shaders
  - Allowed origins: `raw.githack.com`, `raw.githubusercontent.com`
  - Configured in CSP headers (`next.config.ts`)

## Data Storage

**Databases:**
- None - All data stored in static TypeScript files
  - Landscape photos: `data/landscapes.ts`
  - Projects: `data/projects.ts`
  - Roadmap: `data/roadmap.ts`
  - Types: `data/types.ts`

**File Storage:**
- Local filesystem only
  - Images stored in `public/images/` directory
  - Optimized images generated by `scripts/optimize-images.mjs`
  - Service worker caches images locally (via `public/service-worker.js`)

**Caching:**
- Client-side browser caching via service worker
  - Implementation: `public/service-worker.js`
  - Strategies: Static cache (7 days), image cache (30 days), dynamic cache
  - Offline support with fallback to `/offline` page
  - Registration: `components/ServiceWorkerRegistration.tsx`
- Server-side caching headers configured in `next.config.ts`
  - Static assets: 1 year immutable cache
  - Images: 1 year cache with Next.js Image optimization

## Authentication & Identity

**Auth Provider:**
- None - Public-facing portfolio with no authentication
  - No user accounts or login system
  - Contact form uses rate limiting instead of auth

**Rate Limiting:**
- In-memory rate limiting for API endpoints
  - Implementation: `app/api/feedback/route.ts`
  - Limit: 5 requests per hour per IP address
  - Uses `Map<string, { count, resetTime }>` (not production-ready for scaled deployments)
  - IP detection: `x-forwarded-for` or `x-real-ip` headers

## Monitoring & Observability

**Performance Monitoring:**

## Security Features

**Content Security Policy:**
- Configured in `next.config.ts` for production only
- Script sources: Self, unsafe-eval, unsafe-inline (required for Next.js/Tailwind)
- Image sources: Self, data URIs, HTTPS (allow CDN images)
- Connect sources: Self, Vercel Live, GitHub raw content (for Three.js assets)
- Frame ancestors: None (prevents clickjacking)

**HTTP Security Headers:**
- X-Content-Type-Options: nosniff
- X-Frame-Options: DENY
- X-XSS-Protection: 1; mode=block
- Referrer-Policy: strict-origin-when-cross-origin
- Permissions-Policy: Restricts camera, microphone, geolocation

**Service Worker Security:**
- Only activates in production (`NODE_ENV === 'production'`)
- Registration in `components/ServiceWorkerRegistration.tsx`
- Validates responses before caching (status 200 only)
- Implements offline fallback without exposing sensitive data
