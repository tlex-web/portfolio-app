# Phase 12 — UI Design Contract

> Visual and interaction contract for Phase 12 (Contact, Edge Pages, Cleanup & Verification). Generated by gsd-ui-researcher, to be verified by gsd-ui-checker.
>
> **Scope:** `/contact` (header band, "Direct contact" panel, `SummitRegister` form and its states), the shared edge layout and contour art for the 404 (root and group, with the photo/project context link), `(site)/error`, `global-error` and `/offline` (with the saved-pages list), the shared Open Graph image template (default, photo, project), per-route metadata copy, and the D-24 visual carry-over fixes (EndBlock, DemoClip, DemoTerminal, RouteLog, plus dispositions for the three Phase 9 items). Dead-code removal, the service worker, sitemap/robots, CSP and the audit specs are non-visual. They appear here only where they constrain pixels or tests.
>
> **Baseline:** `07-UI-SPEC.md` defines the design system, shell, edge-page skeleton, form field styling and interaction states. `08-UI-SPEC.md` defines the dashed "approx." convention and `ContourField`. `09-UI-SPEC.md` defines the coordinate kicker, the "you are here" accent use and `formatLatLon`. `10-UI-SPEC.md` defines the header band and photo fields. `11-UI-SPEC.md` defines text links, `TrailGradeMark`, `RouteProfile` and the omit-if-no-data rule. This spec **inherits** tokens v2, the four type roles, the spacing scale, motion tokens, focus ring, button variants and every guardrail, and redefines none of them. It adds no colour token, no type size and no motion.
>
> **Source tags:** **[D-NN]** = a locked decision in `12-CONTEXT.md`. **[07]** to **[11]** = inherited from that phase's UI-SPEC. **[FEAT §X]** = `.planning/research/FEATURES.md`. **[PIT #n]** = `.planning/research/PITFALLS.md`. **[REPO]** = repo scouting on 2026-11-02. **[NEXT]** = Next 16.4.2 docs in `node_modules/next/dist/docs/` (version from `node -p "require('next/package.json').version"`). **[UUPM]** = a `ui-ux-pro-max` rule ID or `ux-guidelines.csv` row. **[MEAS]** = computed (contrast from 07's colorjs.io table; widths estimated at Inter 16 px ≈ 8.6 px/char, JetBrains Mono = 0.6 em/char, Schibsted 600 ≈ 0.52 em/char; the executor re-measures). **Default (researcher)** = a value no upstream artifact fixed. Each one is listed in "Defaults to Confirm at Plan Review". **Draft (copy)** = Claude's wording, which ships only after Tim approves it at the copy checkpoint.

| lg | 24px | `6` | Field-to-field rhythm (`gap-6`); summary or failure box → first field (`mb-6`); panel and form-card padding below 1024 (`p-6`); `dl` item gap in the panel (`gap-6`); header band bottom (`pb-6`) |
| xl | 32px | `8` | Card padding from 1024 (`lg:p-8`); last field → submit (`mt-8`); header band → content (`mt-8`); header band top (`pt-8`); edge body → actions (`mb-8`, 07); "Sign again" top margin (`mt-8`) |
| 2xl | 48px | `12` | Contact column gap from 1024 (`lg:gap-x-12`); edge text ↔ art gap (`gap-y-12`, `lg:gap-x-12`); page bottom on phones (`pb-12`); OG plate padding (48 canvas px) |
| 3xl | 64px | `16` | Edge-page top and bottom padding (`pt-16 pb-16`, 07); page bottom from 768 (`md:pb-16`); OG subject-slot padding (64 canvas px) |

**Exceptions (sizes, strokes and canvas geometry, not spacing):**
- **Touch targets:** every link and button is at least 44 px (`min-h-11`; icon-only `min-w-11`) [07]. Saved-pages rows are 48 px (`min-h-12`, the 07 menu-row precedent). Error-summary links are `min-h-11`. The checkbox is 20 × 20 px (`size-5`) inside a `min-h-11` label row, and the label is its hit area. No other target sits within 24 px of it [UUPM `web-target-size`].
- **Component sizes:** the edge art is square, `w-full max-w-md` (448 px), and from 1024 it sits in a `28rem` column. The Contact grid is `lg:grid-cols-[minmax(0,2fr)_minmax(0,1fr)]`. The textarea keeps `rows={6}`.
- **Strokes:** 1 px borders; 2 px focus ring [07]; the edge-art trail is 2 px (`vector-effect="non-scaling-stroke"`), dashed 8/6.
- **OG canvas** (image pixels, not CSS): frame 1200 × 630, subject slot 768 × 630, plate 432 × 630. The photo's letterbox mats come from its own aspect ratio (contain fit, e.g. 59 px for 3:2 in 768 × 630). They are computed geometry, not spacing tokens.
- **Banned (unchanged):** half steps, arbitrary pixel spacing, and 12 px padding (`py-3`/`px-3`) [07, 11]. D-24 removes the last `py-3` (EndBlock) and the arbitrary `top-[39px] -left-[33px]` (RouteLog).

## Typography

Phase 12 uses **exactly four sizes and two weights**, all existing tokens [07]. It does not use `text-hero`.

| Role | Family | Size | Weight | Line height | Tailwind | Phase 12 use |
|------|--------|------|--------|-------------|----------|--------------|
| Label / data | Inter, or JetBrains Mono for data | 14px | 400 / 600 | 20px (1.43) | `text-sm` | Field labels (Inter 600); field errors, helper text, required note, saved-page section labels (Inter 400); the `Summit register` kicker (Inter 600); edge kickers, coordinates, entry timestamp, character counter (Mono 400, tabular) |
| Body | Inter (Mono for the email address) | 16px | 400 / 600 | 24px (1.5) | `text-base` | Intro and body sentences, inputs, panel values, error-box text, register-entry lines (400); buttons, summary title, failure title (600); the email address (Mono 400, D-06) |
| Heading | Schibsted Grotesk | 24px | 600 | 32px (1.333) | `text-heading` | h2: `Sign the register`, `Direct contact`, `Register signed`, `Saved on this device` |
| Display | Schibsted Grotesk | 40px | 600 | 44px (1.1) | `text-display` (base `h1`) | `Contact`, `You've left the marked trail`, `Something went wrong`, `You're offline` |

- **Weights:** 400 and 600 only [07]. Contact's v1 `text-6xl font-bold`, `text-2xl font-bold`, `font-bold` card headings and the offline page's `text-5xl font-bold`/`text-xl` are removed.
- **Mono is data only and always tabular** [07]. Here that means coordinates, timestamps, counts, status codes ("Error 404") and the email address (D-06). Kickers that are plain words (`Summit register`) are Inter 600, the 07 eyebrow rule.
- **h1 at 375:** "You've left the marked trail" is 28 characters. At 40 px Schibsted it wraps to 2 lines within 343 px, with `text-balance` [07; UUPM `heading-line-balance`].
- **No locale APIs** [07, 09]. New pure, unit-tested, import-free formatters:
  - `formatLatLon(pos, { decimals: 2 })`: the 09 formatter gains an optional `decimals: 2 | 4` (default 4, so existing output is unchanged). It gives `47.37 N · 8.54 E` (U+00A0 before N/E, ` · ` between the halves).
  - `formatEntryTime(date)`: `2 Nov 2026 · 14:32`, the visitor's local time from `Date` getters, 24-hour, three-letter month from the fixed 11 table.
  - `formatCount(n)`: `1,950` (comma thousands).
- **No truncation.** Names and emails echoed in the register entry, error text and saved-page titles wrap. The email address uses `wrap-anywhere` with the existing `<wbr>` after "@" [D-06; UUPM `long-token-wrapping`].

### Validation and submit states (CONTACT-02)

| State | Trigger | What renders | Focus |
|-------|---------|--------------|-------|
| Idle | Load, or "Sign again" | Empty form, no messages | Unchanged (load); the **Name** input after "Sign again" |
| Field blurred | Leaving a field the visitor has typed in | That field validates. If invalid: inline error + `aria-invalid` + danger border. An untouched field never errors on blur | Unchanged |
| Field live | Typing in a field that has shown an error | It revalidates on every input event and the error clears the moment the value is valid. The summary updates its list but is not re-announced [Discretion "live once a field has shown an error"] | Unchanged |
| Invalid submit | Submit with ≥ 1 invalid field | Every field validates, inline errors show, and the **error summary** fills the message slot | The summary container (`tabindex="-1"`) [UUPM `focus-management`, `error-summary`] |
| Sending | Valid submit | Button label `Sending…` with `aria-disabled="true"` (not `disabled`, so focus is not dropped to `<body>`); repeat clicks are ignored; fields are `readOnly`; the form-level sr-only status reads `Sending your entry`. No spinner and no motion [UUPM `loading-buttons`, `loading-states`] | Stays on the button |
| Signed | HTTP 200 (`ok`, or the honeypot's success shape) | The **register entry** replaces the form inside the card | The entry container (`tabindex="-1"`) [D-03] |
