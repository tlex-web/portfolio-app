<assumption_delta_decision>
- Signal: `optional` — "The `CaseStudy` template's data-optional sections are driven by the Phase 8 typed highlights."
- Primary noun now: the case-study section (`SectionId` in the fixed `SECTION_ORDER`). Phase 8's schema header said "the tuple order is the render order"; that is no longer true.
- Decision: **promote**. The section id becomes the render key; each highlight block is demoted to a data source that `sectionOf` maps to one section, and sections without data are omitted. The tuple keeps fixing which blocks a project has, not where they render. The schema header comment is rewritten to say so in 11-09 Task 1, together with the schema deltas.
- Invariant test (accepted as a task here): for every project, the rendered h2 sequence is a subsequence of `SECTION_ORDER`, and every block kind maps to exactly one section (or, for the pricing kind until 11-09 removes it, to none). It fails the moment a later change reintroduces tuple-order rendering.
</assumption_delta_decision>
