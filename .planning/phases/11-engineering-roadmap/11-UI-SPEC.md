# Phase 11 — UI Design Contract

> Visual and interaction contract for Phase 11 (Engineering & Roadmap). Generated by gsd-ui-researcher, to be verified by gsd-ui-checker.
>
> **Scope:** `/projects` (header band and route panels), `/projects/[slug]` (case-study template: trailhead, route index, the seven data-optional sections, end block), the CLI_X trail-grade system (`TrailGradeMark`, `RiskScale`, grade and example tables), `DemoTerminal`, and `/roadmap` (header band, filters, `RouteLog`). The shell (SiteNav, SiteFooter with its terrain "Last surveyed", SkipLink), Home and `/photos` do not change. Contact, edge pages and OG images are Phase 12.
>
> **Baseline:** `07-UI-SPEC.md` is the design system, `08-UI-SPEC.md` the margin and dashed-"approx." conventions, `09-UI-SPEC.md` the trail sign, plate and rail conventions, `10-UI-SPEC.md` the header band and segmented control. This spec **inherits** tokens v2, the type roles, the spacing scale, interaction states, motion tokens and every guardrail, and redefines none of them. Where it adds something (three trail primitives, three utilities, two contrast pairs, one formatter), it says so.
>
> **Source tags:** **[D-NN]** = a locked decision in `11-CONTEXT.md`. **[07]** / **[08]** / **[09]** / **[10]** = inherited from that phase's UI-SPEC. **[FEAT §X]** = `.planning/research/FEATURES.md` section. **[ARCH]** = `.planning/research/ARCHITECTURE.md`. **[REPO]** = repo scouting on 2026-11-01. **[NEXT]** = Next 16.4.2 docs in `node_modules/next/dist/docs/`. **[UUPM]** = a `ui-ux-pro-max` rule ID. **[MEAS]** = computed this session (contrast with colorjs.io 0.7.1; text widths estimated from Inter 600 16 px ≈ 9.3 px per character and JetBrains Mono 14 px = 8.4 px per character, to be re-measured by the executor). **Discretion (researcher)** = an item CONTEXT handed to Claude or this spec. **Default (researcher) — confirm at plan review** = a value no upstream artifact fixed; every one is listed in "Defaults to Confirm at Plan Review".
>
> **Content gates (D-21).** Several inputs from Tim are outstanding: the trail pair (D-07), the claims audit (D-09), the Medium and High demo commands (D-10), the per-grade behaviour lines (D-11), link verification (D-12), the route-log dates and `surveyedAt` (D-17, D-20) and all new copy (D-16). For each one this contract specifies **both cases** (input supplied / not supplied). In no case does the UI ship a placeholder, an em dash, "N/A", "TBD" or an invented value: the element is left out, as in 10 D-07.

- **Component sizes:** the profile glyph box is 96 px tall (`h-24`); the risk-scale segment is 56 px tall (`h-14`, the trail-sign plate height [09]); waymark glyph 16 × 12 px; scale waymark stripe 12 px tall (`h-3`, three 4 px rows); example-tick lane 32 px tall (24 px badge + 8 px stem); route-index column 192 px (`12rem`); terminal title and control bars 48 px (`h-12`); camp marker 24 × 2 px [09 rail marker]; status node 8 × 8 px.

## Typography

Phase 11 uses **exactly four sizes and two weights**, all existing tokens. It does not use `text-hero` (Home only).

| Role | Family | Size | Weight | Line height | Tailwind | Phase 11 use |
|------|--------|------|--------|-------------|----------|--------------|
| Label / data | Inter, or JetBrains Mono for data | 14px | 400 / 600 | 20px (1.43) | `text-sm` | Kickers (Mono), metric labels (`dt`), context lines, profile captions (Mono), grade text in badges and the scale (Mono), axis labels (Mono), table cells and headers (600), terminal body (Mono), route-row meta lines (Mono), segment counts (Mono), stack chips |
| Body | Inter | 16px | 400 / 600 | 24px (1.5) | `text-base` | Prose and section intros (400), h3 group labels and route-row titles (600), button and segment labels (600), pipeline stage names (600), route-index links (400) |
| Heading | Schibsted Grotesk (Inter 400 for the outcome line; Mono 600 for metric values) | 24px | 600 | 32px (1.333) | `text-heading` | h2 section and band headings, panel h2 titles; the trailhead outcome line (Inter 400, the 09 thesis precedent); metric values in the instrument panel (Mono 600, the 09 summit-height precedent) |
| Display | Schibsted Grotesk | 40px | 600 | 44px (1.1) | `text-display` (base `h1`) | `Engineering`, the case-study h1 (project name), `Roadmap` |

- **Weights:** 400 and 600 only [07 DSGN-07]. The v1 `font-bold`, `font-medium`, `text-5xl`, `text-xl`, `text-xs` and glow text-shadows on these pages are removed.
- **Mono is data only and always tabular** [07]: versions, scores, ranges, counts, dates, metric values, commands. Titles, prose, labels and buttons are Inter or Schibsted.
- **No locale APIs.** New pure formatter `formatLogDate('2026-10-24')` → `24 Oct 2026` (three-letter English month from a fixed array, the `formatCaptureMonth` table [09]; import-free, unit-tested). Scores print with two decimals (`0.05`), band bounds with one (`0.3`), ranges with an en dash U+2013 (`0.3–0.6`, `T2–T3`).
- **No truncation anywhere.** Text wraps. Separator-joined lines use `whitespace-nowrap` units joined by ` · ` so they break only between units (the 09-16 pattern; 10-UI-REVIEW fix 2 applied to every Phase 11 meta line from the start) [UUPM `truncation-strategy`, `compact-label-overflow`]. Long commands and URLs use `wrap-anywhere` [UUPM `long-token-wrapping`].
- **Headings:** h1 and h2 get `text-balance` [07; UUPM `heading-line-balance`].

## Shared Marks

### `TrailGradeMark` (Server, zero JS) [D-04, D-06, D-11 vocabulary]

One component draws the waymark for a band. Box 16 × 12 px, `inline-flex shrink-0`, `aria-hidden="true"`; it is **always followed by visible grade text** (never alone).

| Marker (`RISK_BANDS[].marker`) | Drawing |
|--------------------------------|---------|
| `yellow` (T1) | A 12 × 12 px diamond centred in the box: `bg-trail` with `clip-path: polygon(50% 0, 100% 50%, 50% 100%, 0 50%)` (the Swiss hiking-trail rhombus) |
| `white-red-white` (T2–T3) | Three stacked 4 px bars, full width: `bg-trail-blaze` / `bg-trail-mountain` / `bg-trail-blaze` |
| `white-blue-white` (T4–T5) | Same, with `bg-trail-alpine` in the middle |
| `unmarked` (T6) | A 16 × 12 px box with `border border-dashed border-ink-muted` and no fill: the 08 dashed "not exact" convention, so it reads as "no paint here", not as a missing image [D CONTEXT discretion; FEAT §RISK] |

The shape differs between T1 (diamond), T2–T5 (bars) and T6 (dashed box); T2–T3 and T4–T5 differ by hue only, which is why the grade and level text are mandatory beside every glyph [UUPM `color-not-only`, `pattern-texture`].

**Badge format (one vocabulary everywhere):** `[glyph] T1 · Low · 0.05` (terminal, examples), `[glyph] T2–T3 · Medium · 0.3–0.6` (band labels), `[glyph] T2` (trail captions). Grade, level and number are Mono `text-sm`; level words are `Low`, `Medium`, `High`, `Critical`; ` · ` separators are `aria-hidden` and each unit is `whitespace-nowrap`.

### Page structure

```
<article aria-labelledby="case-title">
  Trailhead (header band, container)                   back link · kicker · h1 · outcome · links · [RouteProfile ≥1024 right column]
  Body grid (container): lg:grid-cols-[12rem_minmax(0,1fr)] lg:gap-x-12
    RouteIndex   <nav aria-label="Route stages">        sticky list ≥1024 / <details> below 1024
    Sections     <section id="{id}" aria-labelledby>    only those with data, fixed order:
                 problem · pipeline · safety · metrics · demo · stack · next-steps
  End block                                             Next route sign · walkthrough CTA
</article>
```

- **Heading outline:** h1 project name → h2 per rendered section (and the end block has no heading) → h3 for metric groups, stack groups and table-less sub-lists. No skips [UUPM `heading-hierarchy`].
- **Section ids and labels (stable, shareable):** `#problem` Problem · `#pipeline` Pipeline · `#safety` Safety · `#metrics` Metrics · `#demo` Demo · `#stack` Stack · `#next-steps` Next steps. The h2 text is exactly the label.
- **Data-optional rule (ENG-02):** a section renders only if its block has data. No empty heading, no "N/A", no index entry for a missing section. One section renderer per block kind behind an exhaustive `switch (block.kind)` with a `never` check [ARCH].
- **Section rhythm:** each section `mt-16` (first `mt-0`); h2 `text-heading`; intro `mt-4 max-w-prose text-base text-ink-muted`; section body `mt-6`.
- **Focal point:** the trailhead h1 and outcome line lead; inside the body, the risk scale (CLI_X) or the Stack grid (website) is the largest visual. The terminal is subordinate (below Metrics) [UUPM `visual-hierarchy`].
