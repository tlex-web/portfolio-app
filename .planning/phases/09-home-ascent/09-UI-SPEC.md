# Phase 9 — UI Design Contract

> Visual and interaction contract for Phase 9 (Home Ascent). Generated by gsd-ui-researcher, to be verified by gsd-ui-checker.
>
> **Scope:** the Home route only (`app/(site)/page.tsx`). It covers the ascent hero (poster, lazy canvas, pins, altimeter rail, hero copy, trail signs), the four waypoint cards, the summit section (plaque and trail signs), and the short About and contact block below the summit. The shell (SiteNav, SiteFooter with the Phase 8 map margin, SkipLink) is **unchanged**. `/photos` views and the lightbox (Phase 10), case studies and trail grades (Phase 11) and edge pages (Phase 12) are out of scope.
>
> **Baseline:** `07-UI-SPEC.md` is the design system and `08-UI-SPEC.md` the footer and contour conventions. This spec **inherits** tokens v2, the type roles, the spacing scale, interaction states, motion tokens and the guardrails, and redefines none of them. Where this spec adds something (one type size, one L1 primitive, one utility, one generated token module), it says so explicitly.
>
> **Source tags:** **[D-NN]** = a locked decision in `09-CONTEXT.md`. **[07]** / **[08]** = inherited from that phase's UI-SPEC. **[08 D-NN]** = a Phase 8 CONTEXT decision. **[REPO]** = repo scouting on 2026-10-24. **[ARCH]**, **[FEAT]**, **[PIT]**, **[STACK]** = milestone research. **[UUPM]** = a `ui-ux-pro-max` rule ID. **[NEXT]** = the Next 16.4.2 docs in `node_modules/next/dist/docs/`. **Discretion (researcher)** = an item CONTEXT handed to Claude or to this spec. **Default (researcher) — confirm at plan review** = a value no upstream artifact fixed. Every such value is also listed in "Defaults to Confirm at Plan Review".

### Trail yellow (reconciles the mockup, FEATURES and 07)

- **One new L1 primitive** in `:root`: `--trail-yellow: var(--caution-400);` (`oklch(0.84 0.13 85)` ≈ `#f1c45e`). It sits **outside** the `--color-*` namespace, as 07 required for trail colours, so Tailwind generates no `text-*` utility from it and it can never become a text colour [07 "Swiss trail-grade colours"; PIT 4, 22].
- **One utility** in `app/globals.css`: `@utility bg-trail { background-color: var(--trail-yellow); }`. It is the only way to paint trail yellow, and it is used **only** on the trail-sign tip in Phase 9.
- **Phase 11** defines T1 "Low risk" from the same `--trail-yellow` primitive (one source). It may retune the value; Home follows automatically.
- The tip carries no text and no meaning (the sign's label does), so it is decorative and needs no contrast pair. For the record, it measures 11.63:1 against `surface`.
- **Why not a yellow plate:** four yellow fills on one page (two signs × hero and summit) would dilute T1 yellow on the case study [FEAT "Anti-feature: yellow trail-sign styling"] and read as primary buttons [07]. A dark plate with a yellow arrow tip still reads as a Swiss signpost. Default (researcher) — confirm at plan review (options in "Defaults to Confirm" #2).

### Night-tinted relief (D-17)

The Phase 8 hillshade asset stays unchanged [08-06 approval]. On Home it is tinted in CSS:

| Layer (bottom → top) | Spec |
|----------------------|------|
| 1 Ground | `bg-surface` on the stage |
| 2 Relief | The hillshade `<img>` at `opacity: 0.32` (`--relief-opacity: 0.32`, an L1 constant in `:root`), no blend mode. White faces become ≈ `rgb(87 92 99)`, the near-black SE faces stay at `surface`. Default (researcher) — tune once at a visual checkpoint with Tim |
| 3 Contours | `ContourField lod="hero"` (100 m interval, index every 5th) over the `bg-contour` token through its CSS mask [08], filling the sheet box |
| 4 Scrims | In the content track, under the hero copy (see Hero), and the rail scrim in the stage. **Contours sit under the scrims**, so no line runs at full alpha under a glyph |

The 3D shader reproduces layers 1–3 with the same numbers: ground = `mix(night-950, firn-50, shade × 0.32)` in sRGB, contour lines in `firn-50` at alpha 0.14 (index) and 0.084 (intermediate, 60 %), matching the 08 footer convention. Shader colours come from a **generated** `data/generated/tokens.ts` (sRGB hex for `night-950`, `night-900`, `firn-50`, `mist-300`, `glacier-400`, the contour alpha and `--relief-opacity`), built from `app/globals.css` with colorjs.io and `--check`ed in `npm run lint` like the other generated files [07 "tokens are exported from data/generated/tokens.ts there"]. No hex in components.

## Page Structure

```
app/(site)/page.tsx (Server Component; replaces the 'use client' page)
└─ <AscentHero>                                    Server. CSS grid, one cell, two layers:
   ├─ Stage   aria-hidden="true"                    sticky top-(--nav-h), height S, overflow-hidden, @container (size)
   │   ├─ Sheet box (square, side max(100cqw,100cqh)) Poster <picture> + ContourField "hero" + PosterPins (Server)
   │   ├─ TerrainStage slot (Client island)        lazy canvas via SafeCanvas, 3D-projected pins
   │   └─ AltimeterRail (Client)                   hidden below 768 px, rail scrim
   └─ Track   (normal flow, relative)
       ├─ Hero block      height S                   kicker · h1 · role · thesis · TrailSigns · cue links (+ hero scrim)
       ├─ <ol aria-label="Waypoints, lowest first">  one <li> per photo, ascending DEM height
       │    └─ Stage block height S → <section id="waypoint-{slug}" aria-labelledby> WaypointCard
       └─ Summit block    height S → <section id="summit" tabIndex={-1} aria-labelledby> SummitPlaque + TrailSigns
└─ <section aria-labelledby="about-title">         About + contact line (Server)
```

- The stage and the track share one grid cell (`grid` with both children `col-start-1 row-start-1`; the stage `self-start sticky`). No negative margins.
- Everything except the canvas island, the rail and a small focus helper is server-rendered. Nothing from `three` or R3F may be reachable from a Server Component import graph; the canvas is a `next/dynamic` `ssr: false` import made **from a Client Component** [ARCH §5].
- **Heading outline:** h1 "Tim Lui" → h2 per waypoint card (4) → h2 "Matterhorn summit" → h2 "About". No level skips [UUPM `heading-hierarchy`].
- The whole stage is `aria-hidden="true"`: the relief, contours, pins and rail are decorative, and every fact they show is also in the cards and the plaque. The poster image has `alt=""`. The canvas has `aria-hidden` (inherited) and `pointer-events: none`. Default (researcher) — confirm at plan review.
- **Waypoint order and count come from data**: `photos` sorted by `elevation.m` ascending (tie: `id`). With `n` photos there are `n` stage blocks and `n` equal legs (D-01 generalised). Today n = 4. A data set with zero photos fails the build (`lowestDemM` is required) [08].

## Modes

The capability gate picks one of three modes. **Geometry never changes after first paint** (no layout shift, CLS < 0.1) [UUPM `content-jumping`].

| Mode | Trigger | Geometry | Terrain | Rail | Pins | Cards |
|------|---------|----------|---------|------|------|-------|
| **3D** | Gate passes (WebGL2, no Save-Data, `deviceMemory ≥ 4` or unknown, no reduced motion), canvas loaded | Tall: every block height `S` (track = (n + 2) × S) | Canvas over the poster, camera follows scroll | Live readout and marker | 3D-projected, active one lit | Scroll through one per viewport |
| **Static-capability** | No WebGL2, Save-Data, `deviceMemory < 4`, PerformanceMonitor decline, lost context, or 3D not loaded **yet** [D-19] | Tall (same as 3D, decided before JS) | Poster only, holds while scrolling | Live readout and marker | Poster pins, active one lit | Scroll through one per viewport |
| **Static-reduced** | `prefers-reduced-motion: reduce` (CSS media query, so it is known at first paint) | Compact: blocks at natural height, cards stacked with `gap-12` (`motion-reduce:` variants) | Poster only, sticky behind the content | Static profile: ticks and labels, **no** marker or readout | Poster pins, numerals only, none lit | Stacked, final state, story visible at every width |

- Reduced motion is the only trigger CSS can see before hydration, so it is the only one that changes geometry. The other triggers keep the tall layout and fall back to the poster, which is exactly the D-19 "3D not ready yet" state. This refines D-21 ("all four stacked in final state") for the non-motion triggers: the cards are in their final state and in order, but keep one viewport each so the page never jumps. Default (researcher) — confirm at plan review.
- Every mode is a complete Home: hero copy, trail signs, four cards with working links, plaque, About. **No mode shows an error message** [D-21].
- A context lost mid-ascent removes the canvas at once (no fade), shows the poster and poster pins, and switches to static-capability for the rest of the page view. No retry.
- The reduced-motion preference is read reactively (`matchMedia(...).addEventListener('change')`, the `useSyncExternalStore` pattern of `lib/useReducedMotion.ts`); turning it on mid-visit unmounts the canvas [FEAT].

## Ascent Mapping (D-01, D-04, D-06)

Progress `p` = scroll offset inside the track ÷ sticky distance `D` (= track height − `S`; nominally 5 × `S` for four photos). One Motion `useScroll` value feeds **one damped value** (`useSpring`, settling in ≈ 250 ms), and that damped value drives the camera, the rail and the active pin, so they never disagree [ROADMAP scope notes].

**Arrival points are measured, not assumed:** `p_k` is the progress at which block `k`'s centre meets the stage centre, read from the block offsets (ResizeObserver), so a taller hero block (landscape phones) cannot misalign the stages. Nominal values for four photos:

| Block | Nominal `p_k` | Altitude shown | Rail position | Active pin |
|-------|---------------|----------------|---------------|------------|
| Hero | 0.0 | 1,617 m (held) | bottom tick | none |
| 1 Matterhorn from Zermatt | 0.2 | 1,617 m | tick 1 (0/4) | 1 |
| 2 Waterfall in the Gornerschlucht | 0.4 | 1,668 m | tick 2 (1/4) | 2 |
| 3 Matterhorn from the Glacier Trail | 0.6 | 2,585 m | tick 3 (2/4) | 3 |
| 4 Matterhorn in the Riffelsee | 0.8 | 2,760 m | tick 4 (3/4) | 4 |
| Summit | 1.0 | 4,478 m | top tick (4/4) | none; all four numbered |

| Rule | Spec |
|------|------|
| Tilt-in | `p ∈ [0, p_1]`: the camera tilts from the plan view (= poster frame) into perspective over Zermatt. **The rail holds 1,617 m** during the tilt-in (Zermatt is the trailhead). Discretion (researcher) |
| Legs | Four equal legs between consecutive `p_k`. Inside a leg the altitude interpolates linearly between the two real DEM heights, so every number is true [D-01] |
| Plateaus | Within ±0.03 of each `p_k` the altitude holds exactly the waypoint height and the marker sits exactly on its tick, so a centred card always shows its own number |
| Rail scale | Ticks are evenly spaced (a route profile, not a linear altimeter) [D-01]: marker position = leg index + fraction within the leg, ÷ n |
| Active pin | Pin `k` is lit while `|p − p_k| < 0.1`. From `p ≥ 0.9` no pin is lit and all show numerals (the summit view) |
| Damping | ≈ 250 ms ease to the scroll target; `invalidate()` from `useFrame` until the camera is within ε of the target, then stop [D-06; ARCH §5] |
| Large jumps | If the target moves more than one leg at once (`|Δp| > 1/(n + 1)`, e.g. "Skip to the summit", a card link focused from the keyboard, Home/End), the camera and rail **snap** with no damping, so the visitor never watches a fast fly-through [UUPM `motion-sensitivity`] |
