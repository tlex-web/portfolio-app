## Planner decisions (not Tim decisions)

- **The Home list moves to a type-strippable module** so `photos:build` (an `.mjs` script) can import it: `data/home.ts` imports `./site` (extension-less), which Node cannot resolve, while `data/home-waypoints.ts` has only an `import type`, which type stripping erases. Fallback if Node refuses: a JSON id list (`data/home-waypoints.json`) read by both, with a test that it equals `homeWaypointIds`; the same `--root` rule applies to it and `tempPrivacyRoot` then writes `[]` there; record which one was used.
- **photos:build reads the Home list under `--root`, and privacy roots carry an empty one** (plan-checker W1). The Home-id check (`home waypoint <id> has no photo`) would otherwise fail every root whose photo map holds only synthetic records, which is every `tempPrivacyRoot` case from 16-01 and the EPSG:3035 case 16-10 adds. Reading the list from `<root>/data/home-waypoints.ts` follows the script's existing contract (every input and output follows `--root`), keeps the check unchanged for the repository and for every `tempPhotoDataRoot` copy (both hold the real list and the four real Home photos), and needs one write in `tempPrivacyRoot`, so no privacy case changes. Rejected: a selftest-only flag that skips the check (a skip switch beside the guard, and seven spawn sites plus 16-10's to edit); copying the four real Home photos into each privacy root (stage 1 would need their originals, which are gitignored and absent in CI).
- **The generated export is named `homePhotoFacts`**, so it never shadows the `homePhotos()` function.
