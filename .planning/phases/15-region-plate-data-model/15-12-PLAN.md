## Planner decisions and flagged assumption (not Tim decisions)

- **Sidecar fixtures are generated, not committed.** The D-22 `.gitignore` block would ignore committed `.srt`, `.xmp` or `.dat` fixtures, so the selftest writes tiny text files with those extensions into temp roots at run time.
- **The MP4 telemetry-track fixtures are generated too (revised after plan-check: keeps this plan to five files).** RESEARCH "Synthetic telemetry MP4" allows either committing the spliced bytes or building them in memory; this plan builds them in memory, like the G6 originals ("generated, no camera data", selftest.mjs:950). Each clip is `withTrack(goodMp4(), trak(handler, entry))`: a pure function of the committed `good-mp4` clip's bytes with zero timestamps, so every run builds the same bytes, and D-23's "synthetic, never a real drone or camera file" holds. The provenance a per-folder README would carry (as `bad-mp4-uuid`'s does) lives in one comment above the splice helpers. No binary that could be mistaken for camera output enters git history.
- **Flagged assumption A-15-12 (RESEARCH Open Question 3, resolved here as a planner decision pending Tim's review):** a telemetry file that is *tracked* (force-added with `git add -f`) under `assets/photos-original/` or `assets/clips-original/` fails the guard. This reads D-21's "the ignored originals folders stay allowed" as covering ignored, untracked files (which `--exclude-standard` already skips) and D-22's "the guard still catches `git add -f`" as covering tracked ones. It is not a Tim decision; if Tim reads D-21 the other way, the change is one path condition in `collect()` and one selftest case (reversible).
