> Visual and interaction contract for Phase 14 (UI Fixes & Terminal Controls). Generated by gsd-ui-researcher, verified by gsd-ui-checker on 2026-11-14 (7/7).

## Spacing Scale

Inherited unchanged from 07 (multiples of 4 on Tailwind's 4 px base). Phase 14 uses:

| Token | Value | Tailwind | Phase 14 use |
|-------|-------|----------|--------------|
| xs | 4px | `1` | Command line → output in the transcript (`mt-1`, mirrors the terminal) |
| sm | 8px | `2` | Gap between every control in the terminal's bottom bar (`gap-2`: Previous ↔ dot ↔ dot ↔ Next); output → note (`mt-2`); prompt glyph ↔ command (`gap-2`) |
| md | 16px | `4` | Terminal region → transcript (`mt-4`); summary and list horizontal padding (`px-4`); each transcript entry (`py-4`); bar padding (`px-4`, unchanged) |
| lg | 24px | `6` | Demo intro → terminal region (`mt-6`, unchanged) |
| xl | 32px | `8` | Not used new |
| 2xl | 48px | `12` | Terminal bars and transcript summary height (`h-12` / `min-h-12`) — a component size, matching the 11 title bar |
| 3xl | 64px | `16` | Not used new |

**Exceptions (sizes and strokes, not spacing):**
- **Touch targets:** step buttons are `size-11` (44 × 44 px) [D-01; UUPM `touch-target-size`], with 8 px to their neighbours [UUPM `touch-spacing`]. The transcript summary is 48 px tall. Menu rows stay `min-h-12` [07].
- **Focus geometry:** the global ring stays 2 px wide at a 2 px offset [07]. **One scoped exception:** mobile-menu panel links draw it at **-4 px offset** (`focus-visible:-outline-offset-4`), so the ring lies 2–4 px inside the row's own box [D-17]. A stroke offset, not spacing.
- **Scrim geometry:** the rail scrim stays `w-56` (224 px) [D-13]; its gradient stop positions (`via-85%`) are percentages of that width, not spacing.
- **Banned:** arbitrary pixel spacing, half steps, `px-3` [07, 11].

## Contract 1 — Terminal step controls (ENG-06) [D-01, D-02, D-03]

`components/projects/DemoTerminal.tsx`. Title bar unchanged (`{name} · n / count` left, Pause right).

### Layout

The bottom bar becomes `[‹]  • ━ • •  [›]`: a compact cluster, left-aligned like today's dots (it lines up under the title bar's name).

```tsx
<div role="group" aria-label="Commands"
     className="flex min-h-12 items-center gap-2 border-t border-line px-4">
  <button type="button" aria-label="Previous command"
          aria-disabled={atStart ? 'true' : undefined} className={STEP}
          onClick={() => { if (!atStart) step(-1); }}>
    <CaretLeftIcon size={24} aria-hidden="true" />
  </button>
  <div className="flex min-w-0 flex-wrap items-center gap-2">{/* DOT buttons, unchanged */}</div>
  <button type="button" aria-label="Next command"
          aria-disabled={atEnd ? 'true' : undefined} className={STEP}
          onClick={() => { if (!atEnd) step(1); }}>
    <CaretRightIcon size={24} aria-hidden="true" />
  </button>
</div>
```

| Property | Spec |
|----------|------|
| `STEP` class | The `CarouselControls` `STEP_BUTTON` string verbatim: `inline-flex size-11 shrink-0 cursor-pointer touch-manipulation items-center justify-center rounded-sm border border-line-strong text-ink transition-colors duration-(--duration-fast) ease-erosion hover:bg-surface-overlay aria-disabled:cursor-not-allowed aria-disabled:opacity-50 aria-disabled:hover:bg-transparent` — one look for every ‹ › on the site [UUPM `consistency`, `state-clarity`] |
| Bar | Always `min-h-12 items-center` (one row = 48 px, as today's `h-12`). The `count >= 7 ? 'min-h-12 flex-wrap' : 'h-12'` switch is **retired**: only the inner dot row wraps. Previous and Next are `shrink-0`, so they never wrap away from the dots |
| Group | The existing `role="group" aria-label="Commands"` now wraps Previous, the dots and Next. The dot wrapper `<div>` has no role |
| Order | DOM = visual = Tab order: Pause → Previous → dot 1…n → Next [UUPM `keyboard-nav`] |
| Width at 375 px | Frame 343 px, bar inner 311 px. With 4 commands: 6 × 44 + 5 × 8 = **304 px**, one row [MEAS]. With 5–6 commands the dot row wraps to two rows inside the bar while Previous and Next stay vertically centred; nothing scrolls sideways |
| Render rule | Only when `count >= 2`, like the dots (G2 unchanged) |
| No new keys | No arrow-key shortcuts on the terminal (CONTEXT: no new interactions beyond the buttons) |

### Behaviour

| Event | Result |
|-------|--------|
| Previous / Next (enabled) | `goTo(index ∓ 1)`: the target command shows **fully typed at once**, no typing replay (Discretion settled: existing `goTo` semantics). Sets the sticky Pause: the toggle flips to its pressed look (`bg-ink text-ink-inverse`, `aria-pressed="true"`), `data-playback="paused"` [D-02] |
| Any dot, including the current one | Same as a step: shows that command complete and sets the sticky Pause [D-02]. Replaces the 11 D-03 "does not change the sticky state" row |
| Previous on command 1 / Next on command n | `aria-disabled="true"`, `opacity-50`, `cursor-not-allowed`, no hover fill; stays focusable; a press does **nothing**: no state change and no Pause [D-03] |
| Ends during autoplay | Autoplay still loops n → 1; only the manual steps stop at the ends [D-03] |
| Release Pause | Unchanged 11 D-02 amended rule (resumes at once, clears hover and focus pauses) |
| Reduced motion | Starts paused (unchanged); steps work identically; no typing anywhere |
| Screen readers | Unchanged sr-only block "Command {n} of {total}. Command: …. Output: …. {note}" — `aria-live="polite"` while paused, so each step is announced. No new live region |
| Tests | Assert `aria-pressed`, `aria-disabled`, `data-playback`, `data-command` — never classes [D-02; GUARD-03] |

## Contract 2 — Transcript disclosure (ENG-06) [D-04, D-05, D-06, D-07]

A native `<details>` directly after the terminal's `role="region"` element, **outside** it, in the same island's output (a fragment), so it is server-rendered and works without JavaScript.

```tsx
<details data-transcript className="group mt-4 rounded-lg border border-line">
  <summary className="flex min-h-12 cursor-pointer touch-manipulation list-none items-center justify-between gap-4 rounded-lg px-4 text-base font-semibold text-ink transition-colors duration-(--duration-fast) ease-erosion hover:bg-surface-raised group-open:rounded-b-none [&::-webkit-details-marker]:hidden">
    Transcript
    <CaretDownIcon size={20} aria-hidden="true" className="shrink-0 group-open:rotate-180" />
  </summary>
  <ol className="divide-y divide-line border-t border-line px-4">
    <li className="py-4 text-sm">
      <p className="flex gap-2 font-mono">
        <span aria-hidden="true" className="select-none text-ink-muted">❯</span>
        <code className="min-w-0 font-mono whitespace-pre-wrap wrap-anywhere text-ink">{input}</code>
      </p>
      <pre className="mt-1 font-mono whitespace-pre-wrap wrap-anywhere text-ink-muted"><samp>{output}</samp></pre>
      {note && <p className="mt-2 font-body text-ink">{note}</p>}
    </li>
  </ol>
</details>
```

| Property | Spec |
|----------|------|
| Frame | Same width as the terminal; `rounded-lg border border-line`, **no fill** (page `surface`), so it reads as the printed record under the raised "screen". No max-height and no inner scroll [UUPM `scroll-behavior`] |
| Summary | 48 px row; visible and accessible name **"Transcript"**; `CaretDownIcon` 20 on the right rotates 180° **instantly** when open (no transform transition, the 11 precedent); hover `bg-surface-raised` over `--duration-fast`; global focus ring |
| Entries | Every command in order, in an `<ol>` (the count is exposed as a list of n items). Per entry: prompt glyph + command line, captured output **exactly as captured** (leading/trailing blank lines and the `██████████` swatch included; 11 D-26), then the note when present. Rows separated by 1 px `divide-line` |
| Prompt glyph | `aria-hidden="true"` and `select-none`, so a copied command is clean and a screen reader never reads "❯" |
| Text | Plain selectable text, **never `aria-live`** [D-04]. Mono for command and output, Inter for the note, colours as in the terminal |
| Default open state | **Server renders it closed.** After hydration, under `prefers-reduced-motion: reduce`, the client opens it once (the `override ?? reduced` flip pattern). Without JavaScript it stays closed and opens on click. The open state is not stored. A later OS preference change does not toggle it [D-06] |
| Opening presses Pause | A visitor opening it sets the sticky Pause (D-02 rule). Closing it does not resume [D-07]. Under reduced motion Pause is already pressed, so the automatic open changes nothing visible above it |
| Reduced-motion view | The paused, steppable terminal above the open transcript; the duplicate text is accepted [D-05] |
| One command (G2) | **No transcript** (Discretion settled): the G2 terminal is already static and shows the whole command, output and note; a disclosure would only duplicate it. Zero commands: nothing renders (11 IN-01) |
| Motion | None. The native expand is instant; the one-time reduced-motion open shifts content below it only for reduced-motion visitors, and only once [D-06] |
| Test hook | `data-transcript` on `<details>`; tests assert the `open` attribute, never classes |

## Contract 3 — Altimeter rail scrim (HOME-10) [D-13, D-14, D-15]

`components/home/AscentHero.tsx` `data-ascent-rail-scrim`. **Only the gradient stops change**: element, place in the stage, `w-56`, `inset-y-0 right-0`, `hidden md:block` and `pointer-events-none` stay, so `CameraRig`'s `offsetWidth` read (224 px), pin layout and summit pin-clearance tests are unaffected [D-13].

| | Class string |
|--|--------------|
| Before (09) | `pointer-events-none absolute inset-y-0 right-0 hidden w-56 bg-linear-to-l from-surface/85 from-0% via-surface/60 via-70% to-transparent md:block` |
| **After (locked)** | `pointer-events-none absolute inset-y-0 right-0 hidden w-56 bg-linear-to-l from-surface/90 from-0% via-surface/85 via-85% to-transparent to-100% md:block` |

### Why these stops [MEAS]

**Geometry (width-independent at md+):** the stage and the rail layer share the same grid cell and right edge, and every offset is in px. The label run ends `right-8` (32) + tick `w-4` (16) + `gap-2` (8) = **56 px** from the right edge. The longest label, `2,760 m approx.`, is 15 JetBrains Mono characters at 14 px × 0.6 em = **126 px**, so its left edge sits **182 px** from the right edge (81 % of the 224 px scrim). The dense stop at 85 % = **190.4 px** holds one full mono character (8.4 px) past that edge, then fades over the last 33.6 px.

**Alpha:** the old gradient was only ≈ 0.38 behind that label's left edge, which is why it measured 4.81:1 (09 deferred item). The new stops keep alpha ≥ 0.85 behind every label pixel. `ink-muted` (`#aab2bb`) over `surface` at alpha *a* composited over the worst possible pixel behind it:

| Pixel behind the scrim | a = 0.38 (old, at 182 px) | a = 0.80 | **a = 0.85 (new floor)** | a = 0.90 (new right edge) |
|------------------------|------|------|------|------|
| Pure white (absolute bound, any renderer) | 1.17 | 4.91 | **5.89** | 6.96 |
| `firn-50` snow | 1.36 | 5.22 | **6.15** | 7.14 |
| `caution-400` trail paint | 1.79 | 5.84 | **6.66** | 7.49 |
| Brightest poster pixel (white hillshade at `--relief-opacity` 0.32 over `surface`) | 4.94 | 7.73 | **8.06** | 8.37 |

0.85 is the smallest 5-step alpha that clears **5:1 even over pure white** (0.80 gives 4.91), so the 5:1 aim holds on the live canvas whatever it draws, with headroom over the 4.5:1 gate for GPU and antialiasing noise [D-14; UUPM `color-contrast`, "Scrim and modal legibility: measure the composed result"].

Reproduce: OKLCH → linear sRGB → gamma sRGB per token from `app/globals.css` `:root`, `composite = a·surface + (1−a)·bg` per gamma channel, WCAG relative luminance, `(L1+0.05)/(L2+0.05)`.

### Visual effect and acceptance

- The right 190 px of the stage reads as a darker band; terrain under it stays faintly visible through 10–15 %. Pins are unaffected (the pin layers paint above the scrim, 09-19); the readout box (`surface-raised`) is unchanged.
- **Pixel gate (B8 rewritten, never deleted)** [D-15]: Chromium, WebGL on (live canvas) and off (poster), at 768, 1023, 1280 and 1440 px wide, at each waypoint's settled stop and at the summit; readout hidden while sampling (as today); every tick label's worst pixel **≥ 4.5:1** (fails below); the run annotates each value so the ≥ 5:1 aim is visible in the report. Existing N1 rows stay.
- **Geometric gate (Discretion settled):** at the same four widths, for every `[data-tick-label]`, `scrimRect.right − labelRect.left ≤ 0.85 × scrim.offsetWidth`, i.e. every label's left edge lies inside the dense stop. Also assert `scrim.offsetWidth === 224`, so a width change that would move the camera fails loudly.
- Reversible: one class string; one Home PNG re-baseline [D-13].

## Behavioural Acceptance (visual and interaction rows only)

| Fix | What the visitor sees / what holds |
|-----|-----------------------------------|
| **SHELL-07** Current-page tap [D-16] | A plain activation (primary button, no modifier key) of the link whose `href` equals the pathname closes the panel with the existing close motion (`--duration-fast`, `ease-descent`; instant under reduced motion), moves focus to the Menu button as Escape does, and leaves the scroll position untouched (no jump, no visible reload). Focus never drops to `<body>`. The Menu button shows its ring by the browser's `:focus-visible` heuristic (keyboard activation: visible; tap: browser decides); the spec does not force it. Ctrl/Cmd/Shift-click keeps the browser's new-tab behaviour and does not close the panel |
| SHELL-07 other links (Discretion settled) | Links that change the pathname keep today's close-on-route-change path untouched (D-16 literally; zero regression surface). 'Photographs' on `/photos/[slug]` is current but navigates, so it takes this path |
| **HOME-09** Home at 375 px [D-18] | `document.documentElement.scrollWidth <= clientWidth` in every mode and scroll stop. If an element overflows, the fix is at that element and keeps its look (no `overflow-x: hidden` on `html`, `body` or `main`; `overflow-x: clip` only on the element itself if a clamp is still needed). If nothing overflows, no pixel changes and no Home 375 PNG is re-baselined |
| **LBOX-08** Focus on close [D-09, D-10] | Focus on `[data-photo-id="{shown slug}"]`; the trigger **and its ring** are fully in view: the trigger's box inflated by 4 px (2 px offset + 2 px ring) satisfies `top ≥ var(--nav-h)` (64), `bottom ≤ innerHeight`, `left ≥ 0`, `right ≤ clientWidth`. Minimal, instant scroll (no smooth scroll); no movement when already fully visible. The global `scroll-margin-top: calc(var(--nav-h) + 16px)` already clears the nav and ring at the top; **at the bottom `block: 'nearest'` aligns the box edge to the viewport edge and would cut the ring's 4 px**, so the mechanism must leave ≥ 4 px below — recommended `scroll-mb-4` (16 px, on the scale) on `[data-photo-id]` triggers, final mechanism chosen after the D-08 diagnosis. Same outcome for Escape, "Close photo" and browser Back |
| **IN-01** Hidden labels [D-12] | "Hide labels" (button or H) collapses the open callout; showing labels again starts with all callouts collapsed. No new visual state |
