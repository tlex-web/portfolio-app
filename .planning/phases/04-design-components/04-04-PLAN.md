  <name>Task 1: Create GeologicalButton with crystal fracture and mineral dust effects</name>
  <files>components/GeologicalButton.tsx</files>
  <action>
Create `components/GeologicalButton.tsx` as a 'use client' component.

**Interface:**
```typescript
type GeologicalEffect = 'fracture' | 'dust' | 'ripple';

interface GeologicalButtonProps {
  children: ReactNode;
  onClick?: () => void;
  effect?: GeologicalEffect;
  className?: string;
  disabled?: boolean;
  type?: 'button' | 'submit' | 'reset';
  href?: string;
}
```

**Architecture:** Unlike ParticleButton's manual RAF loop, use Framer Motion's declarative animation:

1. **Imports:** React (useRef, useState, useCallback, ReactNode), motion/AnimatePresence from 'framer-motion', EASING/DURATION from '@/lib/animations', useReducedMotion from '@/lib/useReducedMotion'.

2. **Effect system:** On click, generate an array of effect elements (not particles -- these are larger, fewer, more purposeful):

   **fracture effect (default):** 4-6 thin lines radiating from click point. Each is a `motion.div` with `width: 2px, height: 15-30px`, rotated to radiate outward. Color: `var(--color-frost-500)` at low opacity (0.4). Animation: scale from 0 to 1 along their length, then fade out. Duration: DURATION.fracture (0.3s). Easing: EASING.tectonic. Simulates crystal fracture lines spreading from impact point.

   **dust effect:** 6-8 small squares (3-5px) that drift slowly downward from click point. Color: `var(--color-granite-400)` at opacity 0.5. Animation: initial scatter outward (small radius, 20-30px), then slow downward drift with opacity fade. Duration: 0.6s. Easing: EASING.erosion. Simulates mineral dust settling after impact.

   **ripple effect:** 1-2 concentric rings expanding from click point. Each is a `motion.div` with `border: 1px solid var(--color-frost-500)`, `border-radius: 50%`. Animation: scale from 0 to 3, opacity from 0.4 to 0. Duration: 0.5s. Easing: EASING.geological. Simulates tectonic ripple through stone.

3. **Click handler:**
   - If `prefersReducedMotion` or `disabled`, skip effect generation, just call `onClick`.
   - Calculate click position relative to button bounds.
   - Generate effect elements array with unique IDs.
   - Set state with new elements.
   - After animation duration, clear the elements state.

4. **Hover glow:** On hover (if not reduced motion and not disabled), show a subtle frost glow that pulses slowly. Use `motion.div` overlay with `bg-frost-500/5` that animates opacity `[0, 0.08, 0]` with 3s cycle and EASING.erosion. Much more subtle than ParticleButton's radial gradient glow.

5. **Render structure:**
   - If `href` is provided, render as `<a>` element. Otherwise render as `<button>`.
   - Element has `position: relative, display: inline-block` style.
   - Effect overlay: `div.absolute.inset-0.pointer-events-none.overflow-visible` with `z-index: -1`.
   - Inside overlay: `<AnimatePresence>` wrapping the effect elements.
   - Each effect element is a `motion.div` with `initial`, `animate`, `exit` props and `transition` using geological easing.
   - Hover glow overlay inside the element.

6. **Key differences from ParticleButton:**
   - NO requestAnimationFrame loop -- all animations are declarative Framer Motion
   - NO state updates every frame -- AnimatePresence handles lifecycle
   - Fewer, larger effect elements (4-8 vs 20 particles)
   - Muted frost/granite colors (not rainbow colorful)
   - Geological easing (weighty, slow settle) vs easeOut
   - Subtle and refined vs flashy
   - Clean JSDoc comment at top

7. **Do NOT delete ParticleButton.tsx** -- it may be imported elsewhere (demo pages). Just stop using it in production components. Mark it with a comment noting it's superseded by GeologicalButton for production use.
